# T-06 完成自动接收与节流

## 目标

审核后的新目录被运行中的客户端自动接收，用户无需手动下载数据或重启应用。
自动更新与余额刷新、应用安装包更新互不混用状态。

## 范围与责任

负责 Tauri 目录调度、前台事件、独立设置及 UI；
CLI 定价命令入口的有时限自动补检和双语文案；相关契约测试。
复用 T-03 同步接口与 T-05 热刷新，不复制下载逻辑。

1. 默认开启独立的“自动更新模型与价格”开关。
2. 桌面启动和常驻到期检查；Android 启动、回前台及持续前台到期检查。
3. 默认成功检查间隔 6 小时；失败后至少 30 分钟再自动尝试。
4. CLI 普通定价展示命令到期补检总预算 5 秒；失败不改变本地业务成功结果。
5. CLI JSON 默认只读缓存，显式 catalog update --json 才联网。
6. 并发触发合并/节流，手动更新不受成功间隔限制，忙碌时状态明确。
7. 每分钟及 GUI 聚焦/Android 回前台时检查本地缓存版本；接收 CLI 写入的新目录，无需等下一次网络检查。

## 验收

- [ ] 注入时钟验证到期、未到期、失败退避、时钟回退和开关关闭。
- [ ] 桌面首屏直接用本地数据，网络慢时余额刷新和交互不被阻塞。
- [ ] Android 在后台不新增目录轮询或服务，回前台自动补检，持续前台也能到期更新。
- [ ] 多个窗口、前台切换和手动按钮同时触发不会重复覆盖或无限重试。
- [ ] CLI 双通道合计不超过自动预算，退出后不依赖已销毁的后台任务完成更新。
- [ ] CLI JSON 与无关命令不隐式联网；关闭自动开关后手动更新仍有效。
- [ ] 自动成功只更新状态和视图，不弹系统通知或重启确认。
- [ ] 安装包自动更新开关与状态字段保持原有行为。
- [ ] CLI 写入较新缓存后，运行中的 GUI/托盘最迟下一次分钟调度更新；仅重读磁盘、不重复联网。

## 验证

调度纯函数注入时钟；异步入口用 mock 同步接口验证调用次数、超时和前后台切换。
覆盖 V-09/V-10，完成受影响 Rust / 前端门禁及 Android cfg 检查。

这些定时器属于产品实现，不是 Codex automation；不要创建助手定时任务。
完成后记录真实前后台冒烟、提交/PR 和测试证据。
