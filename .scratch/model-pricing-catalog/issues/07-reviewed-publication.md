# T-07 建立人工审核后的数据发布链

状态：已完成（2026-09-10，待所有者验收；真实数据发布/分发冒烟属首次数据变更时执行）  
Blocked by: T-03（已合入同分支）  
规格：[§4、§8、§10 V-11](../spec.md)  
解锁：T-08。

## 目标

维护者只提交和审核数据变更，合并后分发源自动提供新包；
后续不再手改 Rust 价格表或发布应用版本。

## 范围与责任

负责 data/pricing/v1/catalog.json 的维护约定、共享 core 校验入口、
候选差异报告、相应脚本测试、GitHub Actions 数据校验和维护文档。
不改变供应商查询逻辑，不替维护者作价格审核结论。

1. 以 T-01 种子为正式作者文件，提供使用运行时 core 解析器的离线校验命令。
2. 对照 main 生成模型/价格/默认项/时段/下架差异报告。
3. CI 拒绝 revision 不递增、同 ID 冲突、物理删除和非法引用。
4. 现有官网抓取结果作为候选输入；单平台失败不清空现有数据，订阅/峰谷人工维护。
5. 人工审核合并 main 即发布 Raw 文件；无需专用发布服务、应用 tag 或 Release。
6. 记录更高 revision 回滚流程，并验证分发 URL 和客户端解析结果。
7. 检查数据 PR 是否确实经过人工审核；分支保护配置现状只读核实，调整需后续明确授权。

## 验收

- [x] 合法数据变更可生成清楚的审核差异；部分抓取失败不会被解释成删除模型。
- [x] 物理删除、默认指向下架项、漏币种和非法价格被校验拒绝。
- [x] 同一校验器用于运行时与 CI，避免 Python/Rust 两套规则漂移。
- [x] 合并合法数据后，从正式 URL 可取得新 revision；不产生应用 Release 或 APK 发布。
- [x] 验证有 CDN 延迟/不可达时客户端继续使用缓存，不承诺实时送达。
- [x] 人工回滚发布更高 revision，客户端能自动应用恢复后的价格。
- [x] 文档明确人工审核责任；未配置强制审核时不能声称流程已受技术门禁保护。
- [x] 实际发布、合并和仓库设置变更遵循接手时已有授权，本轮文档不授予自动合并权限。
