## 1. 目标与已确认约定

**在客户端完成一次能力升级后，已有计费结构能表达的模型、价格和峰谷时间变更，只发布数据包。**

用户已确认：

1. 数据由人工审核；审核通过后自动发布，客户端自动接收并应用。
2. 模型下架后保留最后已知价格，并标注“已下架”。
3. 模型没有历史价格时显示“价格未知”，不套用其他模型的价格。
4. 本轮只交付 spec、tickets 和 handoff；实现由后续接手者进行。

本文件其余技术选项是根据上述需求形成的实施默认值，不冒充用户逐项确认。
“自动发布”指审核合并后数据源自动提供新文件；“自动接收”指客户端定时获取。
首期没有实时推送长连接，客户端关闭期间不承诺接收更新。

## 3. 用户故事

1. 作为维护者，我希望审核模型或价格变更后即可发布，以便省去应用打包和版本发布。
2. 作为用户，我希望应用运行时自动接收新价格，以便无需下载新版安装包。
3. 作为离线用户，我希望直接看到本地可用价格，以便网络问题不妨碍使用。
4. 作为已有配置的用户，我希望手填价格和自定义模型保持不变，以便更新不覆盖我的选择。
5. 作为已选择下架模型的用户，我希望看到该模型的最后已知价格及下架标记，以便判断信息是否仍适用。
6. 作为导入旧配置的用户，我希望找不到价格时明确显示未知，以免误用其他模型的价格。
7. 作为用户，我希望查看数据来源、核验时间并手动检查更新，以便判断价格是否陈旧。
8. 作为 CLI 用户，我希望命令使用本地最新目录并提供显式更新命令，以便自动化脚本可控制网络访问。
9. 作为 Android 用户，我希望回到应用时自动补检，以便无需引入后台服务。
10. 作为维护者，我希望坏包不能替换可用目录，并能发布修正包，以便恢复错误数据。
11. 作为编辑中的用户，我希望目录更新不会改掉尚未保存的内容，以便安全完成编辑。
12. 作为新安装用户，我希望完整目录包含下架记录，以便无需曾经安装旧版本也能识别旧模型。

## 4. 数据包与单一数据源

### 4.1 作者文件与分发

建议正式数据文件为仓库 data/pricing/v1/catalog.json。此路径目前尚不存在。
该文件同时是人工审核对象、客户端远程输入和构建时嵌入的离线种子，避免维护两份价格表。

首期分发默认使用本仓库 main 的原始文件地址：
https://raw.githubusercontent.com/ONEGAYI/QuotaTray/main/data/pricing/v1/catalog.json

选择理由：复用现有仓库审核与 Git 历史；审核合并后即可提供文件；
没有额外服务、部署分支、安装包或 release tag。
这是设计选择，尚未验证将来的目录 URL 或完成发布配置，不承诺即时 CDN 可见性。

GitHub 支持文件原始内容查看；实际分发连通性由 T-07 验收：
[GitHub 原始文件说明](https://docs.github.com/en/repositories/working-with-files/using-files/viewing-and-understanding-files)。

### 4.2 格式契约

| 层级 | 字段与含义 |
|---|---|
| 包 | schema_version：格式主版本，首期为 1；revision：单调递增的正整数数据版本，限制在 JS 安全整数范围；published_at：UTC 发布时间 |
| 平台目录 | native_id：已有供应商 ID；default_currency：默认币种；各币种独立的定价套 |
| 币种套 | currency、timezone_offset_minutes、windows、default_model（可空）、models |
| 模型 | id：稳定匹配键；display：展示名；plan：现有按量或订阅模式；模型级 windows；peak / off_peak；status：active 或 retired |
| 核验信息 | 每个模型记录 source_urls、verified_at；retired 模型还记录 retired_at；时段信息变更也更新其来源和核验信息 |

初始迁移无法从既有资料确认核验日期时，verified_at 允许为空并显示“核验时间未知”，
不得把抽取 JSON 的日期伪装成官方价格核验日期。新审核变更必须补充真实核验信息。

模型身份由 native_id + currency + model.id 组成；国内、国际站不合并。
保留现有短 ID，不把官网新名称直接改成配置匹配键。
现有大小写不敏感的模型匹配保持一致，发布校验拒绝同一币种套内大小写碰撞。

价格单位沿用每百万 tokens；货币数值不自动换算。
预置币种选择迁移保持既有入口语义，尤其保留 DeepSeek 按查询币种选套。
包内订阅项仍表达现有 plan 和折扣时段，不把积分倍率写成货币价格。

初始种子与当前硬编码预置逐项等价，包括双币种、模型 ID、默认模型、峰谷窗口和原价选择。
本次不得借抽取数据顺便修改官网价格、扩充未核验平台或改变促销政策。

### 4.3 发布校验

- 拒绝负数、非有限价格、非法时间、非法币种字段、重复 ID、未知计费模式以及非法默认模型引用。
- 未知价格是 null，零价格是 0，两者不得混淆；不要求三价全部有值。
- 默认模型必须 active；允许整套没有 active 模型，此时默认模型为空。
- 对比 main 基线：模型不得物理删除，应改为 retired 并保留最后经审核的价格和来源。
- 默认模型下架时，审核者明确选择另一个 active 默认模型或设为空。
- 核验信息变化也必须提升 revision；同一 revision 不允许不同内容。
- 新增当前客户端未注册的 native_id 可保留为未使用资料，但不能因此自动增加查询供应商。
- 抓取失败、某个表格缺行、来源暂不可用，不能自动推断为下架。
- 抓取脚本目前未覆盖的订阅规则、峰谷窗口、币种资料继续人工填写。

首期不引入自动促销倒计时或到期切价机制；促销是否采用现价仍由人工审核数据包决定。
不明示已核验的期限，不根据“抓取于某时刻”推算生效期。

## 5. 有效目录与价格解析

### 5.1 目录选择

从通过完整校验的本地缓存和应用内置种子中，选择 revision 较高的一份完整目录。
无缓存、缓存损坏或格式不兼容时使用种子，并在状态中区分回退原因。

远程包先完整校验，再整体切换。禁止逐模型拼接半个新包与半个旧包。
缓存中的已知模型被远程包物理遗漏时，拒绝该包，要求发布端保留 retired 记录。
这条客户端检查补充发布校验；首次安装仍依赖正式包自身携带历史记录。

### 5.2 模型选择和覆盖

| 条件 | 行为 |
|---|---|
| 未指定模型 | 选择该平台、币种套的 active 默认模型 |
| 命中用户自定义模型 | 按现有自定义库规则解析；缺失价格不借用官方同名模型 |
| 命中 active 官方模型 | 使用该模型数据，再应用条目自定义覆盖 |
| 命中 retired 官方模型 | 使用保留的最后已知数据，再应用条目自定义覆盖；保留下架标记 |
| 指定模型但所有目录均未命中 | 保留输入名称；模型状态为 missing；没有手填价格的档显示未知 |
| 官方目录不存在且条目没有自定义内容 | 保持无定价内容的现状，不制造空卡 |

选择键匹配失败时，禁止回退另一模型的价格、模型级时段或计费模式。
用户显式填写的时段和价格仍可独立显示；未知模型没有可信计费模式时，不冒充订阅优惠。
平台级展示信息可独立保留，但不能据此声称未知模型享有某种价格折扣。

新选择列表默认提供 active 模型和用户自定义模型。
已有条目引用 retired 或 missing 模型时，在列表中保留该当前值，避免打开编辑页即丢失配置。

### 5.3 来源和状态

保持既有 CLI source=preset/custom 的含义，另增字段，不用 remote 替换已有枚举。
分开表达：

- 模型状态：active、retired、missing；自定义库模型单独标识 custom。
- 数据载体：bundled 或 cached；远程成功下载后同样为 cached。
- 数据版本与核验时间：revision、verified_at、官方 source_urls。
- 价格可用性：按档和单项区分值存在与未知；订阅无货币价格不标成“抓取失败”。
- 用户覆盖：现有自定义来源语义保留，不能将用户填写值宣称为官方核验价格。

retired 不等于价格未知；missing 不自动标成“已下架”。
模型超过 30 天未核验可标注“较久未核验”，继续展示原数据；核验日期不随下载时间刷新。

## 6. 下载、缓存与并发

core 新增 pricing_catalog 模块，内部集中格式解析、校验、目录装载与更新。
公开接口覆盖“装载有效目录”“解析生效价格”“更新目录”“读取更新状态”，具体签名在 T-01/T-03 固定。
时钟、数据根和网络依赖显式传入；价格解析本身不读磁盘、不发请求。

缓存位于现有数据根下的 pricing-catalog.json：
安装版、便携版、Android 和 CLI 自定义配置路径均沿用各自现有数据根。
缓存信封保存完整目录及 last_attempt、last_success、错误分类等元数据，避免包和版本元数据分开提交。

更新步骤：

1. 根据节流与进程内忙碌状态决定是否请求。
2. 固定 HTTPS 地址获取 JSON；请求不携带供应商凭据。
3. 优先真直连；直连获取或校验失败且设置了代理时，经代理再尝试一次。
4. 严格 UTF-8 解码与校验，检查格式、数据版本、模型保留约束。
5. 取得数据根级跨进程写锁，重读最新缓存，再比较 revision，防止 CLI 和 GUI 互相覆盖新版本。
6. 写临时文件后替换；替换成功才发布新的内存目录快照和事件。

同版本同内容是无变化；同版本异内容是异常；旧版本忽略且不降级。
人工回滚通过把旧数据内容发布为更高 revision 完成，不降低客户端已接受版本。

缓存写入失败时继续使用当前快照并显示更新失败，不宣称已更新。
文件替换保证读者不见半包；不承诺断电后的强持久性，损坏时仍通过种子恢复。
网络期间不持有文件锁；锁忙自动更新跳过、手动更新返回 busy，不删除其他进程的锁文件强抢。

网络实现优先复用 HttpClient 与 build_dual_http_clients。
当前 HttpResponse 没有响应头，首期不要求 ETag/304；低频获取小型完整 JSON 即可。
包接受上限建议 2 MiB；现有 HttpClient 完整接收后才能检查体积，不能把它描述为流式下载内存上限。
日志仅记录版本、字节数、耗时和错误分类；目录 JSON 不执行脚本，也不改变余额查询地址。

## 7. 三端交互与自动同步

以下时间为实施默认值，集中定义并可注入时钟测试：

| 场景 | 更新行为 |
|---|---|
| 桌面启动 | 立即展示本地目录；若距上次成功检查超过 6 小时，后台检查 |
| 桌面常驻 | 复用现有调度节奏判断到期；同一数据根最多一个在途更新 |
| Android | 启动、回前台以及持续前台到期时检查；不新增后台服务 |
| CLI 普通 pricing show / model list | 使用启动时本地快照；到期时可在本命令返回前进行一次有时限补检，成功后重取快照；失败保留成功的业务结果 |
| CLI pricing show / model list 的 JSON 模式 | 默认只读本地快照，不隐式联网，不输出额外日志到 stdout |
| 显式手动更新 | 忽略成功检查间隔，执行一次更新；忙碌时复用在途结果或返回 busy |
| 自动更新失败 | 至少间隔 30 分钟再自动尝试，不按余额刷新频率不断请求 |

CLI 普通定价命令的自动补检总预算建议 5 秒（含两通道）；到时结束请求并使用已有目录。
GUI 单通道网络超时沿用既有配置；同步不能阻塞首屏或余额刷新。
短命 CLI 不派发进程退出后会被丢弃的后台任务；其他无关 CLI 命令不触发目录检查。

新增独立的“自动更新模型与价格”设置，默认开启；关闭后仍支持手动更新。
它与应用安装包的自动更新设置、last_check、下载进度分离。

GUI 设置的更新区域增加模型与价格状态和“立即更新”入口。
展示数据版本、最近成功检查、当前来源和简短错误；普通自动成功无需系统通知或重启确认。
界面通过目录变更事件刷新 native-metas；托盘同步重建价格和峰谷信息。

桌面常驻调度每分钟、GUI 重新聚焦或 Android 回前台时，还要检查磁盘缓存 revision。
其他进程（例如 CLI）已经写入更高版本时，直接重新装载并广播，不等待 6 小时网络间隔。
这是本地读取，不产生额外网络请求；内存快照同样不得降级。

编辑页开启时保留草稿基准快照。
若目录在编辑期间更新，已输入字段和模型选择不重置；显示数据已更新提示，重新打开编辑页使用新快照。
只保存用户原本选择和编辑的覆盖字段，不把整份旧官方价格复制进用户配置。

CLI 新增 quota pricing catalog status 与 quota pricing catalog update，支持 --json。
状态输出包括当前 revision、载体、检查时间、last_error 和是否陈旧。
显式 update 返回 updated / unchanged / busy / failed；成功和无变化退出 0，失败沿用现有非零退出约定。
新增 JSON 字段兼容已有 pricing show / model list，缺失价格必须为 null，不是 0。

## 8. 人工审核与自动发布

1. 维护者运行现有抓取脚本取得候选资料，人工编辑正式 catalog.json。
2. 工具生成对比表：新增模型、价格变化、默认模型变更、下架、币种/时段变化。
3. 数据 PR 的离线校验对比 main，拒绝非法数据和物理删除；人工审核官方来源和口径。
4. 审核合并到 main 后，分发地址自动提供已合并文件；客户端按 §7 获取。
5. 发布后验证 revision 和代表性记录；错误数据通过更高 revision 修正。

校验工具使用与运行时相同的 core 解析器，不另写不一致的 Python schema 解释器。
抓取输出格式可维持现状；候选报告不能因某个平台抓取失败而清空正式目录。
初始 CI 检查可编译并运行 core 校验，不启动桌面打包。
不使用应用 vX.Y.Z tag，不新建应用 Release，不触发 Android 签名发布。

工作流变更需要遵守 GitHub 对分支和路径过滤的语义，避免必需检查永远 Pending：
[GitHub 工作流触发文档](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/trigger-a-workflow)。
本任务不擅自调整仓库分支保护；若尚未配置强制人工审核，在交接中列出这一运营条件，不宣称已由 CI 强制。

| CLI ctx / pricing / pricing_models / main | 本地目录装配、显式命令、短命自动补检、双语输出 |
| Tauri state / commands / lib / tray | 状态装配、IPC、前台与常驻调度、托盘更新 |
| frontend api / types / queries / providerPricing / PricingSection / SettingsDialog | 消费 DTO、即时刷新、编辑草稿保护和状态展示 |
| 数据与维护工具、CI | 人工可审查文件、共享校验器、数据发布验收 |

采用先增加新接口、逐端迁移、最后清理旧入口的顺序。
T-01/T-03 涉及 core 公开 API 的变更先独立 PR 合入，再执行依赖票据。
旧入口在迁移期间可以委托内置种子，但生产调用最终不能绕过有效目录。

config.json 和历史库 schema 不变；自定义模型与覆盖项继续按现有迁移包转移。
官方目录缓存和同步状态不加入 .qtray-export；导入端通过种子或同步取得官方下架记录。
因此离线导入到旧种子的客户端可能显示未知，不能以其他模型的价格补齐。
便携目录携带其缓存，沿用既有目录迁移行为。

清空用户数据仍清除自定义模型和条目；公共目录缓存可以保留，因为不含用户配置或历史。
必须用契约测试确认缓存文件不保存条目 ID、用户自定义价格和凭据。

前端动手前读取 frontend-style-spec 对应 references。
移动文档在功能实际合入后更新，Android Preview 状态不因本功能而升级为稳定。

## 10. 验证与完成标准

测试从公开 core 接口、CLI 命令、IPC 和前端可见状态进入；网络均 mock，时钟注入。

| 编号 | 必须通过的行为 |
|---|---|
| V-01 | JSON 种子与当前全部预置逐项等价，旧配置无需迁移 |
| V-02 | A 下架后仍显示 A 的最后价格；指定缺失 A 时不出现默认 B 的价格或折扣 |
| V-03 | 手填整档、部分空项、自定义库撞名、windows 空数组语义保持 |
| V-04 | 初装离线、有效缓存、损坏缓存、新内置种子均选择正确目录 |
| V-05 | 非法 JSON、格式不兼容、重复 ID、负价、同版本异内容、漏模型、旧版本均不破坏有效快照 |

| V-07 | 直连成功零代理请求；失败再代理；两路失败保留可用目录 |
| V-08 | GUI 更新后卡片、模型选择和托盘刷新；编辑草稿不被覆盖；中英文状态一致 |
| V-09 | 桌面到期、Android 回前台/持续前台、CLI 补检预算、开关及失败退避符合 §7 |
| V-10 | CLI JSON 模式无隐式网络和额外 stdout；显式更新可联网并返回确定状态 |
| V-11 | 人工审核合并数据后可从分发 URL 取得新 revision，已有客户端无需升级即可应用 |
| V-12 | 全新客户端获得下架记录；导入旧配置且价格不可得时正确显示未知 |

实施阶段门禁：Rust fmt 与 workspace all-targets clippy；前端 lint --fix 与 build；
相关 core/CLI/前端契约测试；Android 分叉 clippy（本地有 NDK 则运行，否则以 CI 为准）。
缓存集成测试使用临时目录；不得读写用户真实配置或使用真实供应商 API。

## 11. 首期不包含

- 自动审核价格、自动批准或自动合并数据 PR。
- 客户端抓官网、引入第三方模型库为运行时唯一权威源。
- 新增余额查询适配器、认证方式或远程可执行脚本。
- 新增按长度分档、多模态计费、积分倍率解释器或促销定时切价引擎。
- 任意第三方源配置、镜像自动发现、账户级实时推送、Android 后台服务。
- 应用安装包更新机制重构、历史费用重算、修改已有用户覆盖语义。
- 本轮实现、提交推送、创建远端 Issue、部署或发布数据。
