# 条目头像：内嵌配置的字符串取值 + 独立写入通道

裁定 2026-11-05（所有者确认）。

供应商头像可从卡片头像悬浮齿轮（Android 长按）打开弹窗更换：挑一个内置品牌图，
或上传自己的 SVG / PNG。头像挂在**条目**而非平台——同一平台的两套 Key 可以各用
各的图，换图不会牵连另一张卡片。

## 取值形态

统一用带前缀字符串表达，不加结构体：

| 取值 | 含义 |
| --- | --- |
| 缺省（不落盘） | 跟随平台品牌图（native 官方 logo；模板/脚本按名称启发或首字母） |
| `brand:<slug>` | 手动指定内置品牌图，slug 与前端资产表对应 |
| `data:image/...` | 用户上传图 |
| `lib:<id>`（预留） | 引用未来「我的头像库」；当前版本按非法值拒绝 |

## 为什么内嵌而不外置

外置文件（`~/.quotatray/avatars/<id>.png` + 配置存文件名）需要新建数据目录、
扩展导出容器、自己实现导入落盘与条目删除时的文件清理，还要开 Tauri asset 协议
才能在 `<img>` 里显示。而本功能的价值全在「换张图」，不值得为它引入一条外置资源
生命周期。

代价是体积：**产出**上限 256 KiB（落盘字符串长度）+ 规整时把 PNG 长边压到 256px
（典型结果 20~160 KiB，源文件上限另为 32 MiB，仅防误选超大文件），
20 条目最坏约 5 MB，远低于迁移容器 16 MiB 上限。

### 导入侧的已知行为：合并模不覆盖同 id 条目的头像

头像随 `config` 载荷走既有导入双模，因此继承 merge 的「同 id 本机为准」语义：
**合并导入不会把备份里的头像写到同 id 条目上**，只有覆盖导入会。

这是 merge 保护本机凭据的既有设计（同 id 整条跳过，备份无法覆盖本机密文），
不是头像的特例。行为由 `merge_import_does_not_replace_avatar_of_same_id` 锁定。
换机恢复想连头像一起还原，用覆盖导入；日常合并备份不必担心本机头像被改。

## 为什么头像不走 upsert_provider

`upsert_provider` 是整条覆盖（`*slot = entry`），而 EditDialog 不组装头像字段。
若头像随 upsert 写入，任何一次「只想改个名字」的编辑都会把它抹掉——`use_proxy`
已经踩过同类坑（见 `EditDialog.tsx` 的保留注释）。

因此：头像只经 `set_provider_avatar` 写入，`upsert_provider` 落地前恒沿用已存值
（`preserve_avatar_on_upsert`）。钩子式分离而非「记得带上字段」，避免下次新增
编辑入口时重蹈覆辙。

## 三层职责划分

- **core**（`avatar` 模块）：纯字符串级校验——前缀、256 KiB 上限、base64 合法性、
  SVG 内容白名单。CLI 也能校验配置文件，不依赖图片库。
- **desktop**（`avatar_import`）：重量级规整——解码、等比缩放、重编码 PNG。
  用户不用自己先压缩：一张几 MB 的 PNG 截图直接可用。
- **frontend**（`avatarView`）：只做形态判别与预览，不做体积/白名单判断，
  避免两侧规则漂移。

**受理格式限于 PNG 与 SVG**（用户需求原话即「svg/png 格式」）。JPEG/WebP 等
不被受理，按 `UnknownFormat` 拒绝并提示转换——放宽到 JPEG 需要额外的解码
feature 与有损格式的取舍判断，不在本功能的范围内。受理按字节魔数判定，
不看扩展名（用户常把 SVG 存成 .txt）。

## 渲染形态分流

- 平台品牌图维持 `contain` 留边——品牌 SVG 的 `viewBox` 差异极大
  （openrouter 401×294、novita 24×15），铺满会裁得认不出。
- 上传图走 `cover` 铺满（`is-upload`），且不套固定浅底——那个底色是为单色深 logo
  的可见性服务的，照片铺底时反而污染颜色。
- **手动选中的内置品牌图仍是 `contain`**（`is-brand`）：它虽属「显式覆盖」，
  但按品牌图规范留边，铺满会裁得认不出；也与挑图格里的 preview 一致，选中后不突变。
- 「底层变灰」用半透明叠加而非 `filter: grayscale`——后者会把彩色合照整张去色，
  视觉上像「图坏了」。
- 未知 `brand:` slug 静默回落到平台默认，不渲染破图。

## Considered Options（未采纳）

- 平台级头像（改一次全平台生效）：悬停入口物理上长在卡片（条目）上，平台级会让
  「换了个图为什么另一张卡也变了」成为隐性副作用
- 现在就做「我的头像库」（上传即入库、所有条目可选用）：需要一套增删改名 UI +
  导入合并时的库并集逻辑，成本是本功能的数倍；`lib:` 前缀已为它留好口子
- 外置文件 + asset 协议：见上文「为什么内嵌」
- 悬停面板行内也放齿轮：28px 容器里放齿轮是纯误触源，且行本身是 `<button>`，
  内嵌会破坏抽屉交互与无障碍语义
- SVG 上传即光栅化：彻底消脚本面，但丢失矢量清晰度且要新增渲染依赖；
  `<img>` 已不执行 SVG 脚本，白名单足够
- 严格拒绝超限图片：实现最简单，但用户会被打断，而自动缩放对用户是无感的
- 按图比例自适应（方形 cover、非方形 contain）：多一个存储状态位，行为不可预测
