# 领域文档消费规则

工程技能在本仓库探索代码前，按以下规则消费领域文档。

## 探索前先读

- 仓库根 `CONTEXT.md`：项目词汇基准（Language 词条定义与避用词）。
- `docs/adr/`：读与工作区域相关的 ADR（设计决策记录，一行一档）。
- **用词**：issue 标题、重构提案、测试命名等输出应使用其中定义的术语，
  不漂移到项目明确避开的同义词（如「历史库」不写成「数据库」）。

## 布局

单一上下文（single-context）：全仓库一个语境，无 `CONTEXT-MAP.md`。

## 决策记录（docs/adr/）

- 沿革：2026-08-22 初始决策快照形成于 AGENTS.md，2026-09-19 外迁为
  ADR 一行一档（`0001`–`0019`，顺序沿用快照表既有次序）。
- 新增决策先过三条件门槛（都满足才建档）：难以逆转、无上下文会惊讶、
  真实权衡。
- 决策经项目所有者确认后建档；修改既有结论需所有者重新确认。
- 编号扫 `docs/adr/` 取最大号递增；文件名中文 slug（`NNNN-决策名.md`）。
- 修订史内联档内「修订记录」节（日期 + 批注原文），不用 superseded 链。
- 建档后经 file-tree 技能 `add` 收录条目（desc 填一句话结论）。

## 与 ADR 冲突时

输出与既有决策记录矛盾时显式标注冲突而不是静默覆盖。
