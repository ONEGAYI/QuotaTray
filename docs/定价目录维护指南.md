# 定价目录维护指南（data/pricing/v1/catalog.json）

> 本文档面向数据维护者：如何修改模型与价格目录、如何审核与发布、
> 出错时如何回滚。技术背景见
> [模型定价目录更新 spec](<../.scratch/model-pricing-catalog/spec.md>)
> （任务包阶段文档）与 core `pricing_catalog` 模块注释。

## 目录是什么

`data/pricing/v1/catalog.json` 是预置定价的**单一数据源**：同一份文件
既是人工审核对象，也是客户端的远程分发源（raw.githubusercontent
地址），并在构建时嵌入应用作为离线种子。价格与模型变更**只需修改
本文件并合并**，不再要求发布应用版本。

## 修改流程

1. **取候选资料**：运行 `python scripts/fetch_pricing/fetch_pricing.py`
   抓取官网定价（DeepSeek/智谱/Z.ai 按量价）。抓取脚本是**候选输入**，
   不是数据源——峰谷窗口、订阅规则、币种资料仍需人工核对维护；
   某平台抓取失败时**不得**清空该平台现有数据（失败 ≠ 下架）。
2. **编辑 catalog.json**：只改价格数字、模型条目（新增/下架）、窗口、
   默认模型与核验信息；`revision` 每次合并**必须严格 +1 以上递增**；
   每个模型填写 `source_urls`（官方定价页）与 `verified_at`（人工核实
   日期，格式 YYYY-MM-DD；无法核实留 null，不得以抓取日期冒充）。
3. **本地校验 + 差异自查**：
   ```bash
   # 单包完整校验（格式/价格/窗口/默认模型引用/生命周期一致性）
   cargo run -p quota-cli -- pricing catalog validate data/pricing/v1/catalog.json
   # 对照 main 基线：审核差异报告 + revision 递增与物理删除检查
   git show origin/main:data/pricing/v1/catalog.json > /tmp/baseline.json
   cargo run -p quota-cli -- pricing catalog validate data/pricing/v1/catalog.json --baseline /tmp/baseline.json
   ```
   校验器与客户端运行时使用**同一个 core 解析器**，不存在第二套规则。
4. **提 PR**：CI 的 `catalog-data` 工作流自动执行同一校验（对比
   PR base 分支基线），非法数据、revision 不递增、物理删除会被拒绝。
5. **人工审核**后合并。合并到 main 即完成发布——raw 文件地址随合并
   更新，客户端按 6 小时节奏（或手动/回前台）自动接收；不创建应用
   tag、不触发 Release 或 APK 构建。

## 关键规则

- **模型下架**：改为 `"status": "retired"` 并填写 `retired_at`，**保留**
  最后已知价格与来源；禁止物理删除记录。默认模型下架时须同时把
  `default_model` 改指其他 active 模型或置 null。
- **价格未知**用 `null`，**零价**用 `0`，不得混淆；三价不要求全有。
- **核验信息变化**（改 source_urls/verified_at）同样要提升 revision。
- 新增当前客户端未注册的 native_id 只是资料（不会自动新增查询供应商）。

## 回滚（错误数据已合并）

不回退 revision：把要恢复的旧内容（可从 git 历史取）以**更高的
revision** 重新发布（例如当前 5 → 回滚内容作为 revision 6 提交合并）。
客户端版本单调不降级，会自动应用恢复后的价格。

## 人工审核责任与门禁现状

- 数据正确性的**责任在人工审核**：CI 只拦非法结构与破坏性变更
  （删除/不递增/非法引用），不判断价格对错。
- 截至本文档撰写时，仓库**未配置强制数据 PR 人工审核的分支保护**；
  审核依赖维护者自觉走 PR 流程。配置分支保护需仓库所有者另行操作，
  本文档不声称流程已受技术门禁强制。

## 客户端行为参考

- 分发源：`https://raw.githubusercontent.com/ONEGAYI/QuotaTray/main/data/pricing/v1/catalog.json`
  （raw CDN 可能有延迟，客户端不承诺实时送达——失败沿用缓存）。
- 客户端拒绝同 revision 异内容与物理删除包；写入失败沿用旧数据。
- 成功、失败和无变化的同步元数据写入均在跨进程锁内重读当前目录，不用旧实例覆盖新价格；
  重启后保留最近成功核验同步的时间。目录同步时间与模型的人工核验日期分别展示。
- 卡片与编辑页可展开「官方模型资料」查看来源和核验日期；没有日期时明确显示未知。
  自定义价格不被标为官方核验。CLI 的 `pricing show/model list --json` 同样透出
  `source_urls` 与 `verified_at`，只读目录命令不会附带应用升级检测。
