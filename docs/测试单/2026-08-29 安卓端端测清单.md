## A. 更新链全链（真机复验）

前置：安装当前正式签名 APK（版本低于待测版本），应用内设置代理端口
留空（直连）；若需代理走 Clash，注意节点出口 IP 可能撞 GitHub API
未认证限流（403），换节点或直连复测。

- [ ] A1 进入设置 → 更新页，进页自动检测一次（距上次检测 ≥5 分钟）
- [ ] A2 手动「Check now」检测出新版本，状态卡显示版本与架构
- [ ] A3 「Download update package」拉起 SAF 保存对话框，预填文件名
      `QuotaTray_<版本>_android-arm64.apk`，保存到 Downloads
- [ ] A4 下载完成显示「Update package saved …」与 Install 按钮
- [ ] A5 点 Install 后的系统行为符合预期分支：
      - Android 8~15：已授权「安装未知应用」时一步拉起系统安装确认页
      - Android 16+（本次主验目标）：安装器被闸口弹回（toast），属实证
        预期——见预研报告第七节，非 bug
- [ ] A6 弹回场景下提示行可见，按提示从系统文件管理器（Files / 厂商
      文件管理器）打开 Downloads 中已保存的 APK，完成安装
- [ ] A7 提示行「去系统设置」链接：跳转本应用的「允许安装未知应用」
      页且应用名/版本正确（Android 16+ 开关置灰为实证预期）
- [ ] A8 同版本重复检测不清空已保存 APK（Install 按钮仍在）；检测出
      新版本后自动失效（回到 Download 按钮）
- [ ] A9 下载中途切后台再回前台，进度显示不中断、不重复下载
- [ ] A10 下载中断网：错误可见且确定性（无重试死循环），恢复后重下成功

## C. 真机通用验收（单场可并测）

- [ ] C1 safe-area 实效：全面屏手势条/刘海不遮挡底部导航与顶部应用栏
- [ ] C2 宽视口（横屏 / 折叠屏展开）：布局不错位，卡片与编辑页可用
- [ ] C3 系统返回键：各页面的 history 栈回退顺序正确，主界面再按返回
      为退出确认（或最小化，按既定语义），不出现卡死或跳空
- [ ] C4 选择器外点关闭：原生选择器/下拉在遮罩外点击可关闭
- [ ] C5 前后台切换：切后台 ≥5 分钟回前台，余额仍显示（不强制清空），
      自动刷新按设置生效
- [ ] C6 系统回收重建：应用被系统杀死后重进，冷启动正常、无崩溃无
      配置丢失
- [ ] C7 文档 URI 迁移：配置导出/导入经 SAF 在真机文件管理器可见、
      可选、可导入（含中文文件名）
- [ ] C8 控制台直达真机差异：余额卡片「控制台」拉起厂商默认浏览器
      正确加载平台页，返回键回应用（模拟器已验 Chrome，真机补厂商
      浏览器差异）
- [ ] C9 悬停/长按等桌面交互不残留在移动 UI（无仅鼠标可触发的入口）
- [ ] C10 厂商 ROM 抽查：如有第二台设备（不同厂商），主链路（查询/
      更新检测/控制台）冒烟通过
