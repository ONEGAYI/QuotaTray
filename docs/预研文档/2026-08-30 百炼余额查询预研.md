- 日期：2026-08-30
- 背景：调研「百炼如何通过 OAuth 接入」以新增余额监视 provider。所有者定向：先做余额查询，Coding Plan 配额搁置。

## 二、OAuth 路线排查（为什么没有 OAuth）

**Qwen OAuth（唯一的真 OAuth）已停摆**。qwen-code 源码（`packages/core/src/qwen/qwenOAuth2.ts`）显示其为 OAuth 2.0 设备码流（RFC 8628）+ PKCE（RFC 7636）：

- 端点：`https://chat.qwen.ai/api/v1/oauth2/device/code` 与 `/oauth2/token`（非官方文档接口，属 Web 界面的一部分）
- scope：`openid profile email model.completion`；token 响应含 `access_token` / `refresh_token` / `resource_url`
- 模型调用走 `https://portal.qwen.ai/v1`（OpenAI 兼容），需 `X-DashScope-AuthType: qwen-oauth` 等专用头

按 qwen-code 官方文档口径：其免费层 **2026-04-15 已停止**，缓存 token 短暂可用后新请求一律被拒，`/auth` 菜单已移除该入口。百炼 Coding Plan FAQ 中 OpenClaw 的「OAuth token refresh failed」条目即此遗留，官方解法为清除旧凭据改用 API Key。

该流程**只用于调模型，从不提供余额查询**。

**易混淆项排除**：

- 百炼「临时 API Key」（`POST /api/v1/tokens?expire_in_seconds=1..1800`，Bearer `sk-` key 换 `st-` 短命 key）：是短命密钥派生，非授权流程；实测可用（200），未来可作 key 有效性探针，与余额无关。
- 阿里云 OAuth 2.1 入站应用（Agent Identity 场景）：面向云服务授权，与费用查询无关。

## 三、`sk-` model key 能力面实测（2026-08-30）

实测凭据：北京地域 `sk-ws` 前缀 model key（Workspace 型）。基线确认 key 有效：`POST /api/v1/tokens` → 200；`GET /compatible-mode/v1/models` → 200。

余额/用量端点探测**全部 404**（服务端确认不存在，非权限问题）：

| 探测端点 | 参照系 | 结果 |
|---|---|---|
| `/api/v1/user/info`、`/usage`、`/balance`、`/me`、`/account`、`/free-quota` | SiliconFlow `/v1/user/info` 模式 | 404 |
| `compatible-mode` 与根域名 × `/dashboard/billing/subscription`、`/dashboard/billing/usage` | OpenAI 老 billing 协议（one-api/new-api 系惯例） | 404 |

旁证（彻底排除）：

- `bailian-cli@1.18.1`（npm 拉包分析）：纯安装器/技能分发器，无业务 API；包内反而引导用户去 RAM 控制台创建 AccessKey。
- 百炼官方 OpenAPI（`bailian/2023-12-29`）全部 **67 个接口**（数据连接/知识库/Prompt/记忆/打赏）中无任何余额、用量、账单、订阅类接口，且鉴权为 AccessKey 签名（ROA 风格），不接受 `sk-` Bearer。

## 四、余额方案：BssOpenApi QueryAccountBalance（实测打通）

### 4.1 接口与实测记录

- 请求：`GET https://business.aliyuncs.com/?Action=QueryAccountBalance&Version=2017-12-14`（RPC 签名风格，全局服务不分地域）
- 凭据：RAM 子账号 AccessKey（`id` + `secret`），权限授 `AliyunBSSReadOnlyAccess`（实测有效，授权即时生效）
- 实测链路：未授权时返回 `400 NotAuthorized`（`AuthPrincipalType: SubUser`，证明签名与 AK 均正确）；授权后 `200` 取回真实余额

实测成功响应结构（金额已脱敏）：

```json
{
  "Code": "200", "Success": true,
  "Data": {
    "AvailableAmount": "xx.xx",
    "AvailableCashAmount": "xx.xx",
    "CreditAmount": "0.00",
    "MybankCreditAmount": "0.00",
    "QuotaLimit": "0.00",
    "Currency": "CNY"
  }
}
```

### 4.2 RPC V1 签名（实现要点）

算法约 40 行纯函数，无第三方依赖（node:crypto / Rust `hmac`+`sha1`+`base64` 即可）：

1. 参数按名 ASCII 排序（排除 `Signature` 本身）；
2. RFC3986 子集 percentEncode（空格→`%20`、`*`→`%2A`、`~` 保留）拼接 `k=v` 用 `&` 连接；
3. `StringToSign = "GET" + "&" + "%2F" + "&" + percentEncode(规范化查询串)`；
4. `Signature = Base64(HMAC-SHA1(AccessKeySecret + "&", StringToSign))`。

**契约测试向量**：官方文档自带（`testid`/`testsecret`/`DescribeDedicatedHosts` 例）期望签名 `9NaGiOspFP5UPcwX8Iwt2YJXXuk=`；本预研原型实现已通过该向量自测与真实请求双重验证。

> 官方同时提供 V3 签名（ACS3-HMAC-SHA256，类 AWS SigV4）并推荐使用；V1 仍普遍可用且实现更简，实现时任选其一，选型在立项时定。

### 4.3 凭据与权限模型

- **双值凭据**：`apiKey`（AccessKeyId，`LTAI` 前缀）+ `apiKey2`（AccessKeySecret）——与 new-api 的 `New-Api-User` 头同为双槽语义，vault 架构零改动。
- **最小权限**：必须引导用户使用专用 RAM 子账号 + `AliyunBSSReadOnlyAccess`；AK 等同账户控制力，禁用主账号 AK。用户操作指引已独立建档（`docs/guide/阿里云余额监控配置指引.md`）。
- **权限 action 口径歧义**（实现时注意）：官方授权文档称 BSS OpenAPI 权限为 `bssapi:【API名称】`，而接口页权限表写 `bss:DescribeAcccount`（三连 c 为文档原文）。本实测走系统策略 `AliyunBSSReadOnlyAccess` 未受歧义影响；若未来提供自定义策略指引，需先实测定稿。

### 4.4 字段口径

| 字段 | 含义 | 展示建议 |
|---|---|---|
| `AvailableAmount` | 可用额度 =（现金余额 + 信控额度）− 未结清 | 主展示 |
| `AvailableCashAmount` | 现金余额 | 可选第二窗口 |
| `Currency` | CNY / USD / JPY | 随主展示 |
| `CreditAmount` / `MybankCreditAmount` | 信控 / 网商银行信用额度 | 忽略或详情页 |
| `QuotaLimit` | 生态客户 Quota 限额（普通账户恒 0） | 忽略 |

**语义红线**：这是**阿里云账户级余额**，不是百炼专属——百炼按量计费扣的确实是它（账号互通），但账户下任何云产品（ECS/OSS 等）的未结清欠费都会拉低可用额度甚至为负。provider 描述与用户文档必须写明该口径。

**国际站未实测**：`business.aliyuncs.com` 为中国站口径；国际站账户的端点与币种（USD）行为实现时需另行验证，指引文档已相应声明。

## 五、Coding Plan 搁置记录（结论存档）

- 官方 FAQ 明确：**无配额查询 API**，仅控制台 Coding Plan 页面可见；额度按「模型调用次数」计，与 token 无关；特定模型用量亦不可查。
- 被动信号仅 429 错误码（`hour/week/month allocated quota exceeded`）。
- 套餐专属配置（背景）：key 前缀 `sk-sp-`，端点须含 `coding`（如 `https://coding.dashscope.aliyuncs.com/v1`），与通用 key/端点混用即报错。
- 破局点为官方开放查询 API；不建议逆向控制台。

## 六、对 QuotaTray 的接入建议

1. **provider**：core 新增 native provider（建议 id `aliyun_bss`），查询走 `QueryAccountBalance`；展示 `AvailableAmount + Currency`，可选双窗口（可用额度/现金余额）。
2. **签名模块**：独立纯函数模块 + 官方向量契约测试；网络一律 mock（项目硬规范）。
3. **错误分类**：`NotAuthorized` / `InvalidAccessKeyId.NotFound` / `SignatureDoesNotMatch` → 确定性失败；`Throttling` → 瞬时失败（keep-last-good）。
4. **GUI 配置指引渲染**：新增阿里供应商入口放「配置指引」按钮，打开渲染器渲染 `docs/guide/阿里云余额监控配置指引.md`。guide 文档按**轻量 Markdown 子集**撰写——块级：h1–h3 / 有序无序列表 / 围栏代码块 / 引用块 / 段落 / 分隔线；行内：粗体 / 行内代码 / 链接 / **图片**（2026-08-30 所有者补充：渲染器预留图片能力，资产源放 `docs/assets/bundle/`（目录暂无图片资产，仅 README 占位））。现有 `InlineMd` 仅覆盖行内两标记，需新做块级渲染组件（`GuideViewer`），实现面以该子集为界。**打包方式已落定**（原「立项时定」）：md 与图片均走 vite import 管线（`?raw` / `?url` glob，收集于 `guideDocs.ts`），文档内引用名与打包产物名经映射解耦，未命中图片渲染占位——dev/build/三端/便携版天然一致，`bundle.resources` 路线（需动 conf/ACL/CSP/便携打包五处）未采纳。
