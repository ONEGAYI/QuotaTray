# 阿里云余额监控配置指引

本指引教你为 QuotaTray 配置**阿里云账户余额**监控（百炼按量计费共享该余额）。全程约 5 分钟，需要能登录 [阿里云控制台](https://home.aliyun.com) 的账号。

> 阅读提示：本文按标题分步组织，每一步自成一块，可按序操作，也可直接跳到遇到问题的步骤。

## 监控的是什么

QuotaTray 查询的是**阿里云账户级余额**（可用额度），不是百炼专属余额：

- 百炼按量计费的扣费来源就是它，充值的钱也在这里；
- 但账户下其他云产品（ECS、OSS 等）的未结清费用同样会占用它；
- 也就是说，这个数字代表整个阿里云账户当前还能花多少。

## 准备工作

查余额用的是阿里云 **AccessKey**（一对访问密钥），**不是**百炼模型 API 里 `sk-` 开头的那种 key——模型 key 没有查询余额的能力。

为了安全，我们不直接使用账号的主密钥，而是创建一个**只有「查费用」权限的专用子账号（RAM 用户）**。主账号密钥泄露等于整个阿里云账户沦陷，而专用子账号泄露只暴露余额数字。

## 步骤一：创建 RAM 用户

1. 打开 [RAM 控制台 - 用户页面](https://ram.console.aliyun.com/users)，点击 **创建用户**；
2. 登录名称随意（例如 `quotatray-readonly`），备注可写「QuotaTray 余额监控专用」；
3. 访问方式**只勾选** `使用永久 AccessKey 访问`；
4. **不要勾选** `使用控制台访问`——本场景只需要 API 调用，开通控制台密码登录会扩大泄露面（阿里云也会在页面给出同样的黄色提示）；
5. 勾选底部的 `我确认必须创建 AccessKey`，点击 **确定**。

## 步骤二：授予费用只读权限

1. 创建完成后进入该用户的详情页，切换到 **权限管理** 标签；
2. 点击 **新增授权**，在弹窗中搜索 `AliyunBSSReadOnlyAccess`；
3. 勾选该策略并确定。这个策略只允许**读取费用信息**，不能消费、不能改动任何资源。

授权即时生效，无需等待。

## 步骤三：创建并保存 AccessKey

1. 回到该用户的 **认证管理** 标签，找到 **AccessKey** 区域，点击 **创建 AccessKey**；
2. 弹窗会显示 `AccessKey ID`（`LTAI` 开头）和 `AccessKey Secret`；
3. **立即复制保存这两个值**——Secret 只显示这一次，关闭弹窗后无法再次查看；若遗失，只能删除后重新创建。

## 步骤四：在 QuotaTray 中添加

1. 在 QuotaTray 中新增供应商，选择 **阿里云余额**；
2. 将 `AccessKey ID` 填入凭据一栏、`AccessKey Secret` 填入第二凭据栏；
3. 保存并立即查询，卡片应显示当前可用额度与币种（中国站为 CNY）。

两个值都会经主密钥 **AES-GCM 加密**后落盘，主密钥保存在操作系统凭据库中，不会以明文出现在任何配置文件里。

## 安全须知

- **专用子账号 + 最小权限**：本文创建的 RAM 用户只有费用只读权限，这是有意为之；请勿为了省事改用主账号 AccessKey。
- **妥善保管 Secret**：不要粘贴到聊天工具、网盘、博客或代码仓库。
- **泄露处置**：若怀疑泄露，立即到该 RAM 用户的认证管理中 **禁用或删除** 对应 AccessKey，再重新创建。

## 常见问题

- **查询报错「NotAuthorized / This API is not authorized」**：说明步骤二的授权没有完成，回到权限管理确认 `AliyunBSSReadOnlyAccess` 已勾选，保存后重试。
- **报错「InvalidAccessKeyId」**：ID 复制不完整或多余空格，重新复制；注意 ID 与 Secret 必须来自同一个 AccessKey。
- **余额数字和预期不符**：先确认口径——这是账户级可用额度，其他云产品的欠费会拉低它；现金充值到账可能有几分钟延迟。
- **百炼模型 key（`sk-` 开头）能用吗**：不能。模型 key 只能调用模型，官方没有提供用它查余额的接口。
- **Secret 丢了怎么办**：无法找回。删除该 AccessKey 重新创建一对，再到 QuotaTray 里更新凭据。
- **国际站（alibabacloud.com）账户**：端点与币种行为暂未在本项目中验证，如有问题请提 issue 反馈。
