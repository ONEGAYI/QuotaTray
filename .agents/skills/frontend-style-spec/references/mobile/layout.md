## T-011 底部导航、顶部应用栏与全屏页面

**信息架构**（2026-08-28 所有者确认；2026-08-30 增消息入口）：账户与使用统计是
底部双导航；顶部应用栏常驻品牌、消息、设置和添加入口（消息为铃铛入口 +
未读红点，面板形态见 T-009 移动形态）。桌面 `TitleBar`、窗口控制、托盘悬停窗
不得出现在 Android。

**布局契约**：

- 顶部应用栏最小高 56px，叠加 `env(safe-area-inset-top)`；内容区不得被状态栏遮挡。
- 底部导航最小高 64px，叠加 `env(safe-area-inset-bottom)`；主内容底部预留等高滚动空间。
- 页面左右内边距 14–16px；卡片保持单列。移动端不以缩放桌面双栏换取塞入更多内容。
- 添加/编辑、设置与确认对话框在 Android 占满可用视口，去除 backdrop 间隙、外层圆角和
  桌面宽度上限；头、正文、底部操作各自固定/滚动，底部操作避让安全区。
- 每个全屏页面压入一层浏览历史；Android 返回键只关闭最上层页面，关闭嵌套确认页后不得
  连带关闭重新露出的编辑/设置页。
- 设置页导航改为顶部横向分段或同页分组，不保留桌面左侧窄栏。

**平台裁剪**：Android 设置页隐藏托盘圆环、自启动、桌面更新安装及 CLI 求助入口；
前台刷新间隔、阈值、语言、主题、代理、系统通知（移动端叠加通知权限行）、
后台刷新（移动端专属，开时叠加周期下拉，2026-08-30 引入）、数据迁移和清空
配置仍保留。

**代码锚点**：`App.tsx`、`MobileChrome.tsx`、`SettingsDialog.tsx`、`ui.tsx` 与
`index.css` 的移动壳层规则。
